# MySurge

面向 Surge iOS 的个人净化模块清单。项目保存经过筛选的模块快照，只对上游文件做换行标准化并统一写入 `#!category=vpromise`；不保存代理节点、订阅或 MITM 证书。

安装页：<https://vpromise.github.io/MySurge/>

## 安装

1. 在 iPhone 或 iPad 上打开安装页。
2. 如果之前已经从旧安装页装过模块，先删除 `Uncategorized` 中的旧副本，再从本页重新安装。
3. 先安装对应 App 的专用模块，并逐个启动 App 验证。
4. 再安装 B 站 1080P 等功能增强模块。
5. 最后安装“开屏及 URL 补漏”和“广告规则拦截”。
6. 在 Surge iOS 中生成并安装自己的 MITM CA，启用 MITM、脚本和 URL Rewrite。

从本项目安装的 28 个模块都会显示在 Surge 的 `vpromise` 分类中。

不要从 Quantumult X 配置复制 `p12` 或证书口令。Surge 应使用设备内自行生成并明确信任的 CA。

## 已知冲突

- “微博净化”和“Vvebo 时间线修复”都会处理 `api.weibo.cn` 的用户时间线接口。两者可以都安装，但不要同时启用。使用官方微博时启用“微博净化”；使用 Vvebo 时停用它并启用 Vvebo 修复。
- “淘宝 / 一淘净化”同时处理淘宝和一淘共用的阿里接口，不需要再为一淘安装重复模块。
- “智行火车票净化”处理 `m.ctrip.com` 共用接口，可能影响携程；携程出现异常时停用该模块。
- “大众点评净化”涉及多个点评及美团静态资源主机名；页面、图片或登录异常时优先停用。
- “云闪付轻量净化”只拦截两个明确广告域名，不启用 MITM，也不触碰账户和支付接口。
- “开屏及 URL 补漏”覆盖面较广。如果出现登录、支付、图片或页面异常，先停用该模块，再停用对应 App 的专用模块。
- B 站净化与 B 站 1080P 已拆分为两个入口，便于独立排错。

## 本轮 App 覆盖说明

- YouTube 已由原有“YouTube 净化”覆盖，没有创建重复模块。
- 一淘由“淘宝 / 一淘净化”覆盖，没有创建重复模块。
- 自如、BOSS 直聘、京粉、成都地铁暂未找到来源可靠且可独立验证的 Surge 原生净化模块，继续由通用补漏承担有限覆盖。
- 个人所得税属于政务和敏感账户 App，本项目不为其添加 MITM 或响应改写。
- WPS 仅保留广告统计拦截，主动排除会员及稻壳解锁。

## 来源策略

- Yfamilys 是本项目认可的主要聚合来源。
- QingRex 和 fmz200 用于补充经过逐项审查、可由 Surge 官方检查器验证的 App 专用模块。
- Yfamilys 当前无法通过 Surge 6.7.0 检查的模块不直接安装；改用同一脚本的原始上游或已经通过检查的 QingRex 转换版本。
- `manifest.json` 同时记录安装地址、原始上游地址与本地快照路径，`sources.lock` 记录同步时的原文哈希。
- 仓库内的第三方模块快照只增加统一分类元数据，不改变规则、脚本或 MITM 内容；原始内容及更新仍由各自作者维护。
- WPS 和云闪付是本项目维护的轻量模块：前者只拦截 WPS 广告统计接口，后者只拦截明确广告域名。

## 本地验证

需要 macOS 上已安装 Surge：

```sh
./scripts/sync.sh
./scripts/validate.sh
```

`sync.sh` 会从清单中的原始地址刷新快照、移除原分类并写入 `#!category=vpromise`。`validate.sh` 会调用 Surge 官方检查器逐项验证，并检查组合配置、统一分类、来源锁和敏感信息边界。
